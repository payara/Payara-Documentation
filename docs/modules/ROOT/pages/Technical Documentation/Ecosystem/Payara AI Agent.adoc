= Payara AI Agent
:ordinal: 3

The Payara AI Agent is an intelligent assistant for Payara Server that lets developers query, diagnose, and administer a running server using plain English.
It is built on https://docs.langchain4j.dev[LangChain4j] and supports any OpenAI-compatible model provider.

The agent is embedded in the xref:/Technical Documentation/Ecosystem/Project Management Tools/Maven Plugin/Payara Server Maven Plugin.adoc[Payara Server Maven Plugin] and is also available as a standalone CLI and MCP server.

NOTE: The AI Agent is an experimental feature. Usage and API compatibility may change in future versions. It is not recommended for use in production environments.

[[capabilities]]
== Capabilities

* Generating and explaining **`asadmin` commands** from plain English instructions.
* Querying server configuration and runtime state via the **Admin REST API** and **JMX MBeans**.
* Automatically executing **read-only `asadmin` commands** (e.g. `list-applications`, `get-config-property`) without user confirmation; write commands are gated unless `PAYARA_AI_ASADMIN_AUTOEXEC=all`.
* Parsing and summarizing **server logs** (`server.log`) and key configuration files such as `domain.xml`.
* Searching **Payara documentation** via a local RAG (Retrieval-Augmented Generation) vector index built from the official Payara Documentation and Jakarta EE Tutorial.
* Checking **MicroProfile Health** and **Metrics** endpoints.
* Enabling and querying the **Monitoring Service** REST tree.
* Cross-referencing server log errors with known **GitHub issues** on `payara/Payara`.

[[quickstart]]
== Quick Start (Maven Plugin)

Enable the agent by setting `PAYARA_AI_AGENT=true` and supplying an API key:

[source,shell]
----
export PAYARA_AI_AGENT=true
export PAYARA_AI_PROVIDER=OPEN_AI          # or OLLAMA, ANTHROPIC, GOOGLE, etc.
export PAYARA_AI_API_KEY=<your-key>
export PAYARA_AI_MODEL=gpt-4o-mini
mvn payara-server:start
----

Once the server is running, a highlighted `payara` prompt appears in the terminal.
Type any natural language query and press Enter:

[source,shell]
----
 payara  why is heap usage so high?
----

The predefined keywords `asadmin`, `deploy`, `undeploy`, and `exit` take priority over AI interpretation when typed exactly.

[[server-connection]]
=== Server Connection

These properties tell the agent how to reach the running Payara instance.
When started via the Maven plugin, `adminPort`, `httpPort`, `domainName`, and `payaraServerPath` are wired automatically; they only need to be set explicitly when targeting a remote server or a non-standard installation layout.

[cols="2,2,2,1,3",options="header"]
|===
|Property Name
|System Property
|Environment Variable
|Default Value
|Description

|Admin REST URL
|payara.ai.admin.url
|PAYARA_AI_ADMIN_URL
|`http://localhost:4848`
|Base URL for Payara's administration REST API.

|HTTP Listener URL
|payara.ai.http.url
|PAYARA_AI_HTTP_URL
|`http://localhost:8080`
|Base URL used for MicroProfile Health and Metrics endpoints.

|JMX Service URL
|payara.ai.jmx.url
|PAYARA_AI_JMX_URL
|`service:jmx:rmi:///jndi/rmi://localhost:8686/jmxrmi`
|JMX connector URL for querying MBeans.

|Domain XML Path
|payara.ai.domain.xml.path
|PAYARA_AI_DOMAIN_XML_PATH
|Derived from `payaraServerPath` + `domainName`
|Absolute path to `domain.xml`. Derived automatically when starting a local server.

|Server Log Path
|payara.ai.server.log.path
|PAYARA_AI_SERVER_LOG_PATH
|Derived from `payaraServerPath` + `domainName`
|Absolute path to `server.log`. Derived automatically when starting a local server.

|Asadmin Path
|payara.ai.asadmin.path
|PAYARA_AI_ASADMIN_PATH
|Derived from `payaraServerPath`
|Absolute path to the `asadmin` (or `asadmin.bat`) binary. Derived automatically when starting a local server.

|Asadmin Auto-Exec
|payara.ai.asadmin.autoexec
|PAYARA_AI_ASADMIN_AUTOEXEC
|`readonly`
a|Controls whether the agent auto-executes asadmin commands.

* `readonly` _(default)_ — auto-execute read-only commands (`list-*`, `get-*`, `ping-*`, `show-*`, `generate-*`, `monitor-*`, `version`, `uptime`). All others are returned as a suggested command text.
* `all` — auto-execute every command without confirmation.
* `off` — never auto-execute; always return the suggested command text.
|===

[[rag-index]]
=== RAG Documentation Index

The agent builds a local vector index from the Payara Documentation and Jakarta EE Tutorial to answer questions about configuration and APIs.
On first use the prebuilt index is downloaded from GitHub Releases (a few seconds).
If the download fails, a local build starts in the background (5–20 minutes on CPU; cached in `<tmpdir>` afterward).

[cols="2,2,2,1,3",options="header"]
|===
|Property Name
|System Property
|Environment Variable
|Default Value
|Description

|Payara Version
|payara.ai.payara.version
|PAYARA_AI_PAYARA_VERSION
|Auto-detected via Admin REST
|Override the Payara major version used to select the correct documentation branch and index. Accepts a bare major (`6`) or a full version string (`6.2025.3`).

|Disable RAG
|payara.ai.disable.rag
|PAYARA_AI_DISABLE_RAG
|false
|Set to `true` to skip the documentation index entirely and save startup time.

|RAG Index URL
|payara.ai.rag.index.url
|PAYARA_AI_RAG_INDEX_URL
|Auto-selected by Jakarta EE version
a|URL template for the prebuilt RAG index. By default the agent selects the correct index automatically based on the detected Payara version and its corresponding Jakarta EE version:

* Payara 5 → Jakarta EE 8 → `payara-docs-index-jakartaee-8.json`
* Payara 6 → Jakarta EE 10 → `payara-docs-index-jakartaee-10.json`
* Payara 7 → Jakarta EE 11 → `payara-docs-index-jakartaee-11.json`

The template supports an `{ee}` placeholder substituted at runtime.
Override this property to point at a custom or internally hosted index file.
|===

[[usage-notes]]
== Usage Notes

* The AI Agent operates best during development, local testing, or in isolated environments.
* It is **not recommended for use in production** due to its access to sensitive runtime data (logs, domain.xml, MBeans) and its experimental nature.
