= Payara Server Maven Plugin Tools in VS Code
:ordinal: 3

Using the Payara Tools VS Code extension, you can integrate the `payara-server-maven-plugin` within Visual Studio Code to streamline development workflows. This integration allows you to:

- Start and stop Payara Server directly from the IDE
- Run Payara Server in dev mode with hot deploy and auto deploy
- Attach the VS Code Java debugger to a running server instance
- Customize build commands via `.vscode/tasks.json`

No plugin declaration in `pom.xml` is required — the plugin auto-selects the Payara Server version based on the project's Jakarta EE dependency.

[[managing-payara-server-maven]]
== Managing Payara Server from VS Code

Any Maven project in the workspace appears in the *Server Projects* panel of the Payara activity bar. The following actions are available by right-clicking a project or using the inline toolbar buttons:

* *Start* — builds and deploys the application, then starts Payara Server
* *Start in Debug Mode* — same as Start, but attaches the VS Code Java debugger when the server is ready
* *Start (Dev Mode)* — starts in dev mode with automatic hot deploy on source changes
* *Start (Dev Mode) in Debug* — dev mode with the Java debugger attached
* *Stop* — stops the running server process

image::vscode-extension/payara-server-maven/server-projects-panel.png[Server Projects panel showing inline action buttons]

Server output streams into a dedicated VS Code *Terminal* panel. The terminal is interactive — you can type input directly and it is forwarded to the running Maven process.

image::vscode-extension/payara-server-maven/dev-mode-terminal.png[Dev mode running in the Terminal panel]

[[dev-mode]]
== Dev Mode

Dev mode enables automatic hot deployment of changes without restarting the server. When a source file is saved, the plugin detects the change and redeploys the updated artifact into the running server.

To start in dev mode, click the lightning bolt icon (*Start (Dev Mode)*) next to the project in the *Server Projects* panel.

[[debug-mode]]
== Debug Mode

When starting in debug mode, the extension waits for the server to print:

----
Listening for transport dt_socket at address: <port>
----

It then automatically attaches the VS Code Java debugger to the advertised port.

[[debug-port]]
=== Configuring the Debug Port

The default debug port is *5005*. On the first debug launch, the extension automatically creates a `payara-server-maven` entry in `.vscode/launch.json`. To use a different port, edit that entry:

[source,json]
----
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "java",
      "request": "attach",
      "name": "payara-server-maven",
      "hostName": "localhost",
      "port": 8000
    }
  ]
}
----

Keep the `name` field as `payara-server-maven` — the extension matches configurations by name.

[[jdk-home]]
== Configuring the JDK

To override the JDK used when running Maven goals, right-click a project in the *Server Projects* panel and select *Configure JDK Home*. The selected path is set as `JAVA_HOME` for the Maven process and is also reflected in the VS Code `java.home` setting for that workspace.

If no JDK is configured, the extension inherits `JAVA_HOME` from the environment.

[[customizing-build-commands]]
== Customizing Build Commands

The extension uses default Maven commands for each action. You can override any command by adding a matching task to `.vscode/tasks.json`:

[source,json]
----
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "payara-server-maven-start",
      "type": "shell",
      "command": "mvn clean package fish.payara.maven.plugins:payara-server-maven-plugin:start"
    }
  ]
}
----

NOTE: The extension writes the default task to `.vscode/tasks.json` the first time it runs an action, so you can edit it in place.

Available task labels:

[cols="1,2"]
|===
|Label |Default command

|`payara-server-maven-start`
|`mvn package fish.payara.maven.plugins:payara-server-maven-plugin:start`

|`payara-server-maven-dev`
|`mvn package fish.payara.maven.plugins:payara-server-maven-plugin:dev`

|`payara-server-maven-stop`
|`mvn fish.payara.maven.plugins:payara-server-maven-plugin:stop`
|===

If your project has a Maven wrapper (`mvnw` / `mvnw.bat`) under `.mvn/wrapper/`, the extension uses it automatically instead of the system Maven.

[[ai-agent]]
== Payara AI Agent

The Payara AI Agent provides an interactive console during server runtime, allowing you to query server state, diagnose issues, and perform operations using natural language or direct `asadmin` commands.

An API key (or local provider location) must always be configured in VS Code settings to activate the agent. Dev mode enables the agent by default once the API key is set; for `start` mode it is also enabled automatically when an API key is configured.

AI agent configuration is passed to Maven as system properties (`-Dpayara.ai.*`) at launch time. The API key is supplied via the `PAYARA_AI_API_KEY` environment variable.

=== Configuration

Set the following in VS Code settings (*File > Preferences > Settings*, search for *Payara*):

[cols="1,2"]
|===
|Setting |Description

|`payara.ai.agent`
|Enable or disable the AI agent (`true` / `false`)

|`payara.ai.apiKey`
|API key for the AI provider (passed as `PAYARA_AI_API_KEY` environment variable)

|`payara.ai.provider`
|AI provider name. One of: `OPEN_AI`, `GOOGLE`, `DEEPINFRA`, `DEEPSEEK`, `GROQ`, `MISTRAL`, `OLLAMA`, `ANTHROPIC`, `LM_STUDIO`, `GPT4ALL`, `CUSTOM_OPEN_AI`

|`payara.ai.model`
|Model name to use with the selected provider

|`payara.ai.providerLocation`
|Base URL for local providers such as Ollama (`http://localhost:11434`) or LM Studio

|`payara.ai.organizationId`
|Organization ID for providers that require it (e.g., OpenAI)

|`payara.ai.customHeaders`
|Custom HTTP headers sent to the provider

|`payara.ai.temperature`
|Sampling temperature (decimal)

|`payara.ai.topP`
|Top-P sampling parameter (decimal)

|`payara.ai.topK`
|Top-K sampling parameter (integer)

|`payara.ai.maxTokens`
|Maximum tokens for the completion

|`payara.ai.maxCompletionTokens`
|Maximum completion tokens (provider-specific)

|`payara.ai.maxOutputTokens`
|Maximum output tokens (provider-specific)

|`payara.ai.presencePenalty`
|Presence penalty (decimal)

|`payara.ai.frequencyPenalty`
|Frequency penalty (decimal)

|`payara.ai.repeatPenalty`
|Repeat penalty (decimal, for Ollama-compatible providers)

|`payara.ai.seed`
|Random seed for reproducible outputs

|`payara.ai.timeout`
|Request timeout in seconds

|`payara.ai.maxRetries`
|Maximum number of retry attempts on failure

|`payara.ai.chatHistoryLimit`
|Number of previous messages to include in each request

|`payara.ai.stream`
|Enable streaming responses (`true` / `false`)

|`payara.ai.chatHistory`
|Enable conversation history (`true` / `false`)

|`payara.ai.logRequests`
|Log outgoing AI requests to the terminal (`true` / `false`)

|`payara.ai.logResponses`
|Log AI responses to the terminal (`true` / `false`)

|`payara.ai.allowCodeExecution`
|Allow the AI agent to execute generated code (`true` / `false`)

|`payara.ai.includeCodeExecutionOutput`
|Include code execution output in AI responses (`true` / `false`)
|===

=== Payara AI Agent Panel

When the AI Agent is active, a dedicated *Payara AI Agent* tab appears in the bottom panel alongside the Terminal. It provides:

* A chat interface — type any question or instruction in the input field and press *Send* (or Shift+Enter for multi-line input)
* Live server metrics such as CPU usage gauges
* Suggested quick actions displayed as buttons on the right side of the panel

image::vscode-extension/payara-server-maven/ai-agent.png[Payara AI Agent panel showing CPU metrics and chat interface]

The status bar at the bottom of the panel confirms connectivity: *Connected to Payara AI Agent*.

=== Sending Commands

You can interact with the running server in two ways:

* Type directly in the *Terminal* panel — keystrokes are forwarded to the Maven process stdin. Supported commands:
** `asadmin <command>` — runs an asadmin command (e.g., `asadmin list-applications`)
** `deploy` / `undeploy` — redeploys or undeploys the application
** `exit` — stops the server
** Any other text — routed to the AI Agent for an intelligent response

* Use the *Payara AI Agent* chat panel to send natural language queries or instructions to the AI Agent directly.
